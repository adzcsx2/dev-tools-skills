# API-First Initialization Capability

Activate only with evidence of backend-owned routes, handlers/controllers, or OpenAPI/Swagger contracts. Client request wrappers alone do not qualify.

## Outputs

Create or incrementally upgrade these project-local artifacts, reusing equivalent existing paths:

- `.ai/tools/api-first/build-api-index.ps1` from `assets/build-api-index.ps1`
- `.ai/tools/api-first/search-api-index.ps1` from `assets/search-api-index.ps1`
- `.ai/index/backend-apis.json`, generated by the build script
- one focused API-first rule under the project's existing AI rules directory, otherwise `docs/references/ai-rules/03-后端接口优先.md`
- one short hard-gate sentence plus the focused-rule path in each generated project-level AI instruction file

Do not create `.ai/skills`, tool mirrors, or a full API catalog in an instruction file.

## Required Rule

For business-capability, data-access, integration, diagnosis, acceptance, or new-endpoint requests:

1. Translate the request into short domain, resource, action, and caller/identity keywords.
2. Search the project index first. Rebuild it when missing or stale.
3. Verify candidates against route registration, handler/controller, DTO/schema, service/repository flow, and auth middleware. Code is authoritative; OpenAPI and docs are secondary.
4. Report method/path, caller and authentication boundary, relevant inputs/outputs, and the evidence for match or mismatch.
5. Reuse a safe match. Propose a new public contract only after verified searches show that none fits.

Searching and inspection are read-only. They do not authorize calling state-changing endpoints or exposing an internal/admin or user-scoped endpoint to a different caller.

## Installation

- Copy the two assets without embedding repository-specific secrets or paths.
- Build the index with `pwsh -File .ai/tools/api-first/build-api-index.ps1 -WorkspaceRoot <root>`.
- If the generic scanner reports incomplete coverage, adapt only the project-local builder to the repository's actual route-registration pattern and keep the output schema compatible with `references/index-schema.md`.
- Run a representative natural-language search. Inspect the highest candidate in real code before declaring the capability ready.

Read [references/index-schema.md](references/index-schema.md) only when generating or adapting the project-local builder.

## Verification

- The index contains no duplicate method/path pair.
- Every indexed item has at least one source path and line when code evidence exists.
- Search reports stale inputs instead of silently trusting old data.
- A known endpoint is discoverable from business-language keywords.
- A repository without backend-owned APIs does not receive these artifacts.
