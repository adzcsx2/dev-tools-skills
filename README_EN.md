# dev-tools-skills

A shared toolkit for Claude Code, Codex, and VS Code Copilot, including complete plan execution, universal project init, common tools, Android tools, and Flutter tools.

## Installation

**macOS / Linux:**

```bash
git clone git@github.com:adzcsx2/dev-tools-skills.git
cd dev-tools-skills
./install.sh --all
```

**Windows PowerShell:**

```powershell
git clone git@github.com:adzcsx2/dev-tools-skills.git
cd dev-tools-skills
.\install.ps1 -All
```

`--all` auto-detects and installs to tools already present on the machine. To install only for Claude Code or Codex, run `./install.sh` or `.\install.ps1` and choose the target tool; for category selection, see `./install.sh --help`.

`install.sh` and `install.ps1` auto-detect Claude Code, VS Code Copilot, and Codex. Claude Code installation clears old cache entries, stale registrations, and the previous marketplace directory before reinstalling the latest version from `.claude-plugin/plugin.json`, so Claude does not keep using an older cached skill.

For cleanup only, use:

```bash
./uninstall.sh
```

```powershell
.\uninstall.ps1
```

The uninstall scripts also clean Claude Code plugin state, VS Code Copilot prompts, and Codex skill wrappers, prompt aliases, and the sync script generated by this toolkit.

Installation also registers global prompts for VS Code Copilot and syncs Codex-compatible skill wrappers (for example `$do-all`, `$dt-init`, `$dt-push`). Codex `/prompts:*` aliases are disabled by default; set `DEV_TOOLS_SYNC_CODEX_PROMPTS=1` if you need the legacy prompt aliases.

## Included Skills

### Common Tools — `do-all` and the `dt:` prefix

| Skill                      | Description                                                                                                                                                                                                                                                                                                                                                                             |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `do-all`                   | Complete plan execution: infer or wait for the unique target plan, execute every phase in order, and advance only after strict test gates pass; use `/do-all` in Claude and `$do-all` in Codex                                                                                                                                                                                         |
| `dt:init`                  | Universal project init: detect the real stack, generate AI rules/docs/hooks, load evidence-selected capability plugins (API-first discovery for backend projects, semantic-driven UI automation rules for Flutter apps), and when direct child Git repositories exist, isolate them, initialize root Git, and locally commit or push root according to its real remote state                                                                                                                                                |
| `dt:init-root`             | Multi-repository product-root init: run `dt:init` and `dt:update-docs`, maintain child `.gitignore` entries and `.ai/init-root.yml`, locally commit a root without a remote, and sync, commit, and push a root with a usable remote                                                                                                                                                          |
| `dt:study`                 | Study verified skill mistakes: capture them back into the workspace source skill and avoid cached copies                                                                                                                                                                                                                                                                                |
| `dt:push`                  | One-push release workflow with strict preview, upstream sync, logical commits, push, explicit `--squash`, and optional tags; multi-repository roots process every child first, then locally commit or push root according to its live remote state                                                                                                                                          |
| `dt:execute-loop`          | Serial execution loop: run the same follow-up command + prompt through fresh subagents, defaults to 3 runs and supports `-N`                                                                                                                                                                                                                                                            |
| `dt:update-remote-plugins` | Remote plugin maintenance: update docs and config, then verify install-based local refresh uses the latest version                                                                                                                                                                                                                                                                      |
| `dt:code-note`             | Multi-language code annotation: auto-detect language and apply comment style                                                                                                                                                                                                                                                                                                            |
| `dt:to-public-cloudflare`  | Cloudflare tunnel: one-click Named Tunnel setup, auto-detect project port, deploy global tunnel management scripts (tunnel-add/start/stop/remove/list) with health monitoring and auto-restart                                                                                                                                                                                          |
| `dt:install-project-hooks` | Project hook installation: generate Claude/Codex final rule audit hooks and serve as the single registry for future project hooks                                                                                                                                                                                                                                                       |
| `dt:work-report`           | Daily work report: generate a non-technical Chinese work summary from git log and uncommitted changes (each item ≤ 30 chars), supports natural-language date args, and appends actionable improvement suggestions                                                                                                                                                                       |
| `dt:local-worktree`        | Isolated local dev worktree: pass the original repo path, create a sibling `local` branch worktree (`remote-<x>`→`local-<x>`), run dt:init, audit and rewrite README, and guarantee init artifacts (CLAUDE.md/.ai/.claude/docs) never pollute the original branch and never get pushed (CLAUDE.md rule + PreToolUse hook). Merges real source back via a whitelist-only checkout script |
| `dt:update-docs`           | Cross-platform doc generator: auto-detects Android/Flutter/other project types, audits code changes first, then updates all affected docs |
| `dt:codex-sync-push`       | Codex config sync push: save safe local Codex config, hooks, prompts, and user skills into this repository, then run `dt:update-remote-plugins` |
| `dt:codex-sync-pull`       | Codex config sync pull: apply the repository snapshot to the current macOS, Windows, or Linux machine and sync hooks, prompts, and user skills |

### Android Tools — `adt:` prefix

| Skill                          | Description                                                             |
| ------------------------------ | ----------------------------------------------------------------------- |
| `adt:gradle-build-performance` | Diagnose and optimize Gradle build performance |
| `adt:android-i18n`             | i18n: audit hardcoded strings, generate multi-language resources |
| `adt:android-fold-adapter`     | Foldable screen: diagnose and fix fold adaptation issues                |

### Flutter Tools — `fdt:` prefix

> Flutter doc updates have been merged into `dt:update-docs`, which auto-detects Flutter projects and applies corresponding rules.
